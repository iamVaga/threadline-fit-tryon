# FitCheck

FitCheck helps shoppers choose a size across Threadline's eight fictional apparel categories and offers a separately labelled virtual try-on for consented adult team members. The size recommender uses prior fit outcomes, brand and category offsets, cut, stretch and optional consented measurements. Fit & Returns shows aggregate brand evidence. The data and customer IDs are synthetic.

[Public demo](https://threadline-fit-tryon.onrender.com) · [October metrics](results/metrics.json) · [Image credits](CREDITS.md) · [Fit & Returns note](FIT_AND_RETURNS.md)

## Current evidence

The October model results, confidence reliability table, breakdowns by label source, category and history, and failure examples are generated by `train_recommender.py`. Read the [generated report](results/metrics.json) for denominators and the [recommender audit](RECOMMENDER_AUDIT.md) for the model comparison. The target for overall within-acceptable accuracy is 85%. The target for **Kept after exchange** is 60%. Both are currently missed.

Shopper first choice scores 86.202% within acceptable overall and zero on exchange cases by construction. The October set includes kept and exchanged orders and excludes size refunds without an exchange. The comparison with usual size uses the same subset of shoppers with a recorded usual size. It does not estimate live causal impact.

The 120-case grid contains zero evaluated renders in this checkout. The workbook's worked example is excluded. Quality, body-type and skin-tone parity, p95 and cost remain **not run**. Use the sample gallery for publication-approved results when available. An empty gallery is shown explicitly.

The A/B plan starts at **40,532 sessions per arm** with an assumed 3.9% baseline, a 10% relative lift, 80% power and a two-sided 5% significance level under an independent-session approximation. Scaling the 5,078 bot-filtered September women’s kurta sessions by 25 gives an assumed 126,950 eligible company sessions per 30 days. That traffic reaches the sample target in three whole weeks. Plan **four whole weeks** so that weeks 2–4 can be reported separately. Confirm assignable company traffic and inflate for repeated sessions per customer before launch. Randomise by customer with sticky assignment, analyse purchase conversion by intention-to-treat, and measure size-related returns 30 days after purchase. The workbook's measured 229 purchases from 5,078 sessions (4.51%) are separate from the design baseline.

## Reproduce and run

Extract the original five PS-13 files into `data/`. Source data, photos, private outputs and secrets are ignored by Git.

```bash
python -m pip install -r requirements-training.txt pytest
python train_recommender.py
python -m pytest -q
docker build -t fitcheck .
docker run --rm -p 8000:7860 -e MOCK=1 fitcheck
```

For local Python instead of Docker, download the two MediaPipe assets shown in the Dockerfile to the repository root and run `python -m uvicorn server:app --port 8000 --no-access-log`. The build verifies both downloaded hashes. Training uses January–September observations with recorded outcomes before October. Early September selects the challenger and late September calibrates confidence. Height strings are cleaned for audit. Height and weight are excluded as noisy signals. The inference artifact contains synthetic fit signals without raw measurements or October labels. At startup the server indexes test cases by ID and by customer and SKU, and pre-serializes their responses. Recommendation responses report handler time in `Server-Timing` and the page reports end-to-end time separately.

## Run an open model and evaluate

1. Use [the bake-off notebook](notebooks/tryon_bakeoff.ipynb) on a GPU with four approved garment-only kurta photos and three consented adult or authorized research-dataset person photos. It compares CatVTON, IDM-VTON and FASHN VTON v1.5. The notebooks and GPU adapters have not been run on a GPU in this checkout. FASHN is the initial serving candidate. There is no measured winner yet.
2. Run `gpu_worker:app` on the GPU host. Set a private `TRYON_HTTP_TOKEN` in both the worker and the app, and set `FASHN_WEIGHTS` in the worker. Start it with `uvicorn gpu_worker:app --host 127.0.0.1 --port 7860 --no-access-log`. Use HTTPS if the web service reaches it through a tunnel or separate host. Keep user images out of tunnel request logs, notebooks saved with outputs and Git.
3. In Render, set `MOCK=0`, `TRYON_REMOTE=1`, `TRYON_BACKEND=local_http`, `TRYON_HTTP_URL` to the worker's full `/render` endpoint, and securely add `TRYON_HTTP_TOKEN`. `hf` is an explicitly selected open-model fallback with a separate consent disclosure and `HF_TOKEN`. It may queue or fail. Use a host with acceptable photo retention and no-training terms. Gemini needs both `TRYON_BACKEND=gemini` and `ALLOW_GEMINI_PHOTOS=1` plus a verified no-training service configuration. It is outside the scored demo. Use the default worker or leave remote inference unavailable until provisioned.
4. Follow [render_grid.ipynb](notebooks/render_grid.ipynb) to supply exact-SKU photos and consent evidence in a private manifest. The CLI preserves completed files on resume and tracks failed and unrun cases. Review and fill human scores in `renders/grid.csv`, then run `python grid_eval.py report`. The CLI writes a filled workbook and fairness report. Use the original workbook in `data/` and keep `renders/` private.
5. Publish only labelled real renders with explicit display rights, via an operator-controlled `static/gallery/manifest.json`. Each entry has `case_id`, `image` (PNG filename) and `publication_approved: true`. Use eligible public dataset renders with redistribution permission for persistent showcase examples. Personal team renders stay private and expire within 24 hours or sooner on request.

The garment image mapping in `static/products/products.json` maps catalogue SKU to an approved garment-only filename. Upload a flat-lay or mannequin image for SKUs without mapped photos. Catalogue illustrations are not valid try-on inputs.

## Privacy and limits

Photo and measurement opt-ins are separate. Photo try-on is team-only and 18+. FitCheck sends photos to the disclosed configured host only after consent and preflight. It never trains on photos. The in-memory GPU worker returns an image without saving a persistent file. The web service deletes its session images on request and after 24 hours. Operators must clear evaluation copies separately. Brands see aggregates. Every generated preview is labelled “Simulated preview — fit, colour and drape may differ from the actual product.” Size advice comes from the recommender.

The PNG composite copies original pixels outside the binary clothing mask. A classifier can still mislabel image regions. Verify face, hair, body and skin-tone preservation with human review before counting a run as acceptable. Restrict the demo to approved subjects.

The daily cap defaults to 150 attempts per UTC day and the session cap is three. Invalid uploads reserve no slots. The daily ledger and latency log are local to the single Render service. Render's ephemeral filesystem can reset them. `/api/metrics` reports the count and server-side p50 and p95 for successful real renders. Cost is blank without measurements. If the operator sets `TRYON_ESTIMATED_GPU_HOUR_INR`, estimated cost is shown separately, assuming the entire server render time is billed at that hourly rate. Use provider invoices or metering for the scored cost target.
